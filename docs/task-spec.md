# 新增任务指南（task-spec）

> 目标：新增一个评测任务**只写一个 YAML 文件，不改判分器代码**。
> 前置阅读：[judge-schema.md](judge-schema.md)（字段规范）、[failure-taxonomy.md](failure-taxonomy.md)（失败码）。

---

## 三步流程

### 第 1 步 · 写任务 YAML

1. 复制 `tasks/` 中最接近的示例（关节角类 → `close_centrifuge_lid`；放置类 → `place_tube_on_balance`）为 `tasks/<task_id>.yaml`；
2. 按字段规范填写：`task_id`（snake_case 全局唯一）、`language_instruction`（与训练数据指令一致）、`criterion`、`metrics_sources`、`failure_rules`；
3. 关键决策点（写 YAML 前先想清楚）：

| 决策 | 规则 |
|---|---|
| **latch** | 铰链开合类（盖/门，到位后有小回弹）→ `true`；放置/称重类（举起又放下算失败）→ `false`。不写 = schema 错误 |
| **阈值参照系** | 涉及"运动增量"（抬起/推/关）→ `ref: initial` 相对开局基线；涉及绝对位置（放到某个台面）→ 绝对值 + `target_source` |
| **单位与坐标系** | `metrics_sources.unit` 必须显式写；`prim_path` 由 sim 适配器解析，评估器不感知 |
| **粘滞** | 掉落/倾斜类灾难条件必须 `sticky: true` |
| **兜底** | 全表**恰一条** `default: true` |

### 第 2 步 · 合成轨迹自测（不开仿真）

1. 在 `tests/cases.py` 仿照现有用例，为本任务至少构造 6 类轨迹：**黄金成功 / 保持不足 / 粘滞失败 / 边界恰好等于阈值 / 抖动分段保持 / 指标缺失（F0）**；
2. `pytest tests/ -v` 全绿（evaluator 未实现期跳过，实现后必须全绿）；
3. 帧数自查：hold_s ÷ dt = 所需连续帧数；注意**进入区域首帧**若移动 delta 超差（step_delta 条件）不计入保持——构造轨迹时到达后至少多静止 1 帧。

### 第 3 步 · 真实轨迹校准

1. 采集 **5–10 条**遥操作轨迹：成功 ≥3 条 + **故意制造的失败**（掉落 / 放偏 / 超时各 ≥1 条）——失败样本比成功样本更值钱；
2. 判分器输出 vs 操作员当场自评逐条比对；不一致的**逐帧回放**定位分歧帧；
3. 此步目标是验证**量纲与读取正确性**（sim 单位、坐标轴朝向、角度约定、prim 路径稳定），不是一致率——专抓"指标读错轴"这类低级但致命的错；
4. 顺带实测采集端反馈延迟（终局汇总 + 落盘应在毫秒级，3 秒预算的大头留给 episode 收尾）。

## 判据标定方法

阈值从哪来（按优先序）：

| 来源 | 适用 | 例 |
|---|---|---|
| **设备校准表** | 关节角/行程类 | 真实盖铰链行程 -60°→0°，误差 ≤2° → 阈值取行程中点侧 |
| **专家轨迹分布直方图** | 连续保持值类 | 专家夹爪输出的逐帧分布画出来，阈值取语义端点外侧 |
| **稳定容差实测** | step_delta 类 | 静止段相邻帧变化的实测噪声幅度 × 安全系数（如 2×） |

标定记录写进任务 YAML 同目录的 `<task_id>.calibration.md`（一页即可）：每条阈值一行——数值 / 来源 / 测量条件。判据改动时同步更新。

**开工第一件事（血泪教训）**：若任务涉及夹爪/连续保持类动作，**先画专家策略的输出分布直方图**，确认是二值还是连续保持值，再定阈值、再采数据——语义冲突在数据采集后才发现，代价是整批数据作废。

## 常见坑

1. **分段保持 ≠ 连续保持**：hold_timer 离区清零。"分两段各 1s" 不满足 `hold_s: 1.0`——防抖动假阳性的代价，标定阈值时有意识权衡；
2. **latch 选错的典型症状**：铰链任务用了 `latch: false` → 到位后回弹被翻盘成 F2；放置任务用了 `latch: true` → 抬起又放下被记成功；
3. **阈值方向写反**：F3 高占比时先查 `op` 方向与铰链建模方向（如盖子角度定义是开还是合为零点）；
4. **prim 路径漂移**：场景重建后 prim_path 变化 → 表现为 F0 高发；路径稳定性是适配器侧职责，任务 YAML 只声明不硬编码解析逻辑；
5. **抖动误判 F2**：真实在区但噪声让 delta 超差 → 加大 `obj_z_step_delta` 容差或降低控制频率，**不许动 hold_s**（判据单一权威）。
